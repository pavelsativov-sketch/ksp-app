# Инструкция для публикации KSP App

Краткая передача контекста для ИИ или разработчика, который будет собирать и публиковать проект. В этом файле намеренно нет паролей, токенов, API-ключей и содержимого `.env.local`.

## Как устроен production

- Единственный публичный адрес приложения: <https://ksp-app-pi.vercel.app>.
- Основное Next.js-приложение публикуется в Vercel. Проект уже привязан к Vercel как `ksp-app`.
- Браузер рабочей области живёт в той же персональной Vercel Sandbox, что и файлы/терминал. Код раннера — `src/lib/agents/sandbox-runner-code.ts`, загрузка и прогрев — `src/lib/agents/sandbox-browser-service.ts`. RPC-подпись к раннеру — производный от `AUTH_SECRET` секрет на пользователя (`getRunnerRpcSecret`), глобальный `AUTH_SECRET` в песочницу не попадает.
- Cloudflare Browser Run, GitLab Shared Runner, Codespaces-раннер и локальный раннер на компьютере пользователя **удалены**: раннер живёт только внутри песочницы. Переменные `AGENT_RUNTIME`, `BROWSER_RPC_URL`, `BROWSER_RPC_SECRET` больше не читаются; `npm run check:deploy` падает, если они остались в production-конфигурации.
- Публикация идёт только в Vercel. Другого раннера и второго хоста для ОС в проекте нет.
- Рабочая область — веб-интерфейс с окнами и вкладками. Команды рабочего стола выполняются в изолированной Vercel Sandbox, а удалённые сайты — в браузере внутри неё же. Это не установка ОС на компьютер пользователя и не доступ к его локальным файлам.
- Агент и вкладка «Браузер» работают с одной сессией: `getAgentBrowserSession` — единственная точка входа. Если появится второй браузерный backend, действия агента перестанут быть видны учителю.
- Вне Vercel браузера и терминала ОС нет: `npm run dev` отдаёт вкладке «Браузер» честную 503, а интерфейс пишет, что рабочая область работает только на опубликованном сайте. Это сделано намеренно: никакой интеграции с компьютером пользователя (ни команд на его машине, ни Chromium на его ПК). Код раннера проверяйте локально через `node scripts/check-runner.mjs` — он гоняет тот же скрипт, что уезжает в песочницу.
- Шрифты: образ песочницы приходит без них, поэтому `INSTALL_SCRIPT` ставит Noto Sans в `~/.fonts`, а Chromium запускается с локалью `ru-RU`. Без этого кириллица и казахские буквы рисуются «квадратиками» («иероглифами»).
- Песочница остывает между занятиями, поэтому вкладка «Браузер» пингует `/api/health/browser-keepalive` раз в 10 минут. Эндпоинт требует авторизации: серверный cron его прогреть не может.

## Перед публикацией

1. Убедись, что работаешь в папке проекта и ничего не потеряешь:

   ```powershell
   git status --short
   git branch --show-current
   git remote -v
   ```

   Не используй `git reset --hard`, `git clean` и не заменяй весь `.env.local`. Не добавляй секреты в Git. Не публикуй незнакомые изменения без просмотра diff.

2. Установи зависимости и проверь изменения:

   ```powershell
   npm ci
   npm run typecheck
   npm run lint
   npm run test
   npm run build
   ```

3. Проверь в Vercel → `ksp-app` → Settings → Environment Variables, что обязательные Production-переменные заданы. Сверяй только наличие/окружение, не выводи значения в лог, markdown, Git или чат.

4. Убедись, что проект привязан к ожидаемому Vercel-проекту и production-домену. Для CLI доступна команда:

   ```powershell
   npx --yes vercel@latest deploy --prod --yes
   ```

   CLI должен быть авторизован в нужном аккаунте. После команды дождись `READY` и проверь production alias; не считай успешную отправку сборки успешным релизом.

## Переменные окружения

### Обязательные для production-приложения

Добавь значения в Vercel Environment Variables для Production. Секреты не должны попадать в этот файл или в репозиторий.

| Переменная | Для чего нужна |
| --- | --- |
| `MONGODB_URI` | Подключение к MongoDB Atlas |
| `AUTH_SECRET` | Подпись сессий и шифрование сохранённых данных браузерной сессии; минимум 32 символа |
| `RESEND_API_KEY` | Отправка писем, включая восстановление доступа |
| `MAIL_FROM` | Подтверждённый адрес отправителя Resend |
| `APP_URL` | Production URL приложения: `https://ksp-app-pi.vercel.app` |

`MONGODB_DB` необязателен; по умолчанию используется база `ksp`.

### AI-провайдеры

Добавляй только те ключи, которые действительно настроены и разрешены для использования. Для AI-функций нужен хотя бы один доступный провайдер:

- `GROQ_API_KEY`
- `GEMINI_API_KEY`
- `XAI_API_KEY` или поддерживаемый приложением alias `GROK_API_KEY`
- `CEREBRAS_API_KEY`
- `OPENROUTER_API_KEY`
- `OPENAI_API_KEY` (если используется)

Не вставляй реальные ключи в команды, которые печатают окружение, и не показывай значения через `vercel env pull`/логи.

### Браузер рабочей области

- Ничего настраивать не нужно: `AUTH_SECRET` из общего списка используется и как подпись RPC-вызовов к раннеру. Если он короче 32 символов, браузер не запустится вовсе.
- Первый запуск поднимает Chromium внутри песочницы и занимает около минуты; вкладка «Браузер» повторяет попытку сама и показывает экран «Запускаю браузер…».
- Установка Playwright идёт под атомарным локом в песочнице (`/tmp/pw-lock`), поэтому параллельные запросы не портят `/tmp`. Логи установки и раннера: `/tmp/pw-install.log` и `/tmp/runner.log`.
- Песочница остывает между занятиями; её греет пинг `/api/health/browser-keepalive` из вкладки «Браузер» раз в 10 минут. Эндпоинт требует авторизации, поэтому в `vercel.json` нет cron: серверный прогрев без пользователя невозможен.
- Локальная проверка раннера без Vercel: `node scripts/check-runner.mjs` — поднимает ровно тот код, что уезжает в песочницу, и прогоняет 17 проверок (DOM, `evaluate` обоих видов, `storageState`, drag, SSRF-guard, 410).
- Сквозная проверка «приложение → раннер → Chromium» живёт в `tests/integration/os-browser-flow.test.ts` и входит в `npm test`: поднимает раннер и гоняет настоящие модули приложения. Ловит рассогласование между ними — например, агент получал пустой список кликабельных элементов из-за выполнения `INTERACTABLES_SCRIPT` в Node вместо страницы.
- Полный сценарий учителя с настоящей моделью — `npm run test:agent` (`tests/live/agent-login.test.ts`). Агент реально получает задачу «авторизуйся по логину и паролю и открой дашборд», сам обнаруживает форму входа, передаёт управление учителю, после ручного входа возвращается к работе и доводит задачу до дашборда. Цель — локальный сайт-заглушка с вымышленными учётными данными; реальные школьные логины не используются. Тест тратит квоту AI-провайдера, поэтому не входит в `npm test` и CI. Ключи берутся из `.env.local`, база — отдельная на тест и удаляется после прогона.
- Ещё два живых теста: `os-user-journey.test.ts` — вход руками учителя через настоящий роут с замером каждого шага; `os-typing-latency.test.ts` — защита от возврата к прежней медленной схеме.
- **Дымовая проверка живой ОС на проде** — `node scripts/smoke-production.mjs`. Единственная проверка, которая проходит настоящий путь учителя через развёрнутый Vercel: Vercel Sandbox по OIDC, установка Playwright и системных библиотек, раннер, Chromium, переход на страницу с формой, распознавание поля пароля и ввод. Логинится тестовым учителем (`node scripts/seed-test-accounts.mjs 1 <адрес>`), учётные данные в вывод не попадают, форму входа не отправляет. При сбое печатает то, что видит учитель на экране, и тело последнего ответа бэкенда — по ним причина находится сразу.
- Отзывчивость ввода. Локально (раннер рядом) одно нажатие — 1 запрос в песочницу и ~190 мс. На проде раньше выходило ~2 секунды на кадр: функции работают в `bom1`, а песочница по умолчанию создавалась в `iad1`, и каждый кадр ходил через Атлантику дважды. Песочница теперь создаётся в регионе функций (`SANDBOX_REGION`, по умолчанию `bom1`), а регион входит в имя песочницы — иначе `getOrCreate` возвращал бы песочницу из своего снапшота в старом регионе. Замер на проде после правки: кадр ~600 мс, ввод пароля ~550 мс, холодный запуск песочницы 10–70 с.
- Прочие находки живой проверки: команда запуска раннера убивала сама себя (`pkill -f` находил собственную командную строку — теперь снятие и запуск разнесены на два вызова, есть тест-инвариант); образ песочницы приходит без системных библиотек Chromium (`libglib-2.0.so.0`), поэтому `playwright install-deps chromium` входит в подготовку; фоновый опрос кадра затирал адрес, который учитель печатает, — поле больше не синхронизируется, пока в фокусе; значение поля пароля возвращалось открытым текстом в заголовке `X-Active-Field` — теперь только точки.

### Только если используется соответствующая интеграция

- `ADMIN_USER_IDS` — идентификаторы администраторов.
- `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `SENTRY_DSN`, `OPENAI_MODEL` и `WORKSPACE_RUNTIME` — задавай только при подтверждённой необходимости текущей конфигурации.

## После публикации: ручная проверка

1. Открой `https://ksp-app-pi.vercel.app/api/health`; проверь HTTP 200 и доступность MongoDB в ответе.
2. Проверь вход и переход на `/school`.
3. Открой `/school/workspace`: переключи вкладки рабочего стола, запусти ОС, открой/сверни/разверни окно, проверь, что нижняя часть интерфейса не перекрывается белой полосой и доступно главное меню.
4. Создай небольшой файл в рабочем пространстве, перезагрузи страницу и проверь, что файл сохранился.
5. Проверь один небольшой AI-запрос и убедись, что задача и результат отображаются без ложного статуса «выполнено».
6. Открой внешний сайт во вкладке «Браузер», кликни по полю ввода на скриншоте и набери текст с клавиатуры: рамка активного поля и мгновенный эхо-ввод должны появиться, после `navigate` вкладка не должна просить войти заново.
7. Запусти агента, который должен что-то открыть, и убедись, что его действия видны на том же экране браузера. Это главная проверка единой сессии.
8. Для BilimClass пользователь должен сам вводить свои учётные данные; не сохраняй пароль школы в тестовых сценариях, логах или документации.
9. Проверь страницу deployment в Vercel и последние runtime logs. Если приложение открылось, но рабочая область или база не работают, релиз не считать полностью проверенным.

## Команды проекта

- `npm run dev` — локальный запуск.
- `npm run typecheck` — TypeScript-проверка.
- `npm run lint` — ESLint.
- `npm run test` — Vitest.
- `npm run test:e2e` — Playwright smoke test.
- `npm run build` — production-сборка Next.js.
- `node scripts/check-runner.mjs` — живая проверка браузерного раннера ОС (16 проверок, секрет генерируется сам).

## Важные ограничения для следующего ИИ

- Не проси пользователя присылать пароли, MongoDB URI, AI API-ключи, `AUTH_SECRET` или Cloudflare-токены в чат. Настраивай их непосредственно в панели соответствующего провайдера как encrypted secrets.
- Не публикуй приложение вторым Cloudflare Worker: публичный production host здесь только Vercel. Браузерный Worker из проекта удалён вместе с Cloudflare Browser Run.
- Успешный build не доказывает, что рабочая область функционирует в production. Проверяй опубликованный URL после каждой production-публикации.
- Не обещай бесплатную или неограниченную работу без проверки текущих лимитов Vercel, MongoDB Atlas, Resend и Cloudflare в аккаунтах пользователя.
