# Работа агента с BilimClass.kz

## Текущий статус

Прямой API-интеграции **нет**. Раньше существовал адаптер-заглушка
`src/lib/bilimclass/client.ts`, который ни разу не импортировался, а при
настроенных переменных окружения возвращал `ok: false` — то есть тихо
проваливался. Заглушка удалена, чтобы мёртвый код не выглядел как рабочая
функция. Этот файл хранит план, чтобы он не потерялся.

Выбранный путь: пользователь сам входит в свой BilimClass в изолированном
браузере, а агент выполняет поручения по видимому интерфейсу. Пароль не
передаётся агенту. Предметные инструкции находятся в
`src/lib/agents/domain-skills/bilimclass.ts`; опасные изменения защищены
подтверждением учителя в `src/lib/agents/computer/safety.ts`.

Это не fine-tuning модели: агент получает предметный playbook при задаче о
BilimClass или работе на домене `bilimclass.kz`, а интерфейс и данные читает
с экрана. Изменения оцениваются отдельно тестами и требуют проверки на
реальном аккаунте пользователя.

При безопасном осмотре учительского аккаунта подтвердились разделы
«Моё расписание», «Чат с учеником», «Мои уроки», «Мои СОР/СОЧ» и «Журнал»;
также видны пункты управления школой, мониторинга, отчётности и аналитики.
В списках журнала есть фильтры по параллели и языку обучения, а также вкладки
основных, дополнительных, всех журналов и классного руководства. Доступность
части пунктов зависит от роли. Личные записи учеников не используются как
материал обучения агента.

Основной сценарий, который нужно автоматизировать: отметить проведение
урока, заполнить его тему и выдать домашнее задание. Официальная инструкция
для учительского приложения описывает эти действия в карточке урока; статус
проведения нельзя изменить после отметки. Поэтому отметка и сохранение ДЗ/темы
всегда останавливаются перед финальным действием и требуют подтверждения.

## Что нужно для полноценного использования

1. Пользователь входит в BilimClass самостоятельно через браузер агента.
2. На живом аккаунте проверяются роли, разделы и конкретный рабочий процесс.
3. Для любого изменения учебных записей требуется подтверждение пользователя
   и проверка результата на экране.
4. Если BilimClass в будущем предоставит официальный API и владелец школы
   выдаст сервисные права, API можно добавить отдельным адаптером.

Переменные окружения прямому API-адаптеру (сейчас не используются):

```
BILIMCLASS_API_URL      — например, https://api.bilimclass.kz
BILIMCLASS_API_TOKEN    — сервисный токен организации
```

## Отложенная прямая API-интеграция

**Шаг 1. Клиент и схемы.** `src/lib/bilimclass/client.ts` — реальный HTTP-клиент
на `fetch` с таймаутом и повтором. Zod-схемы ответов. Клиент скрывает за собой
`LessonPlanRow` и отдаёт наружу `BilimClassPushResult` (уже был такой тип).

**Шаг 2. Маппинг КСП.** Написать `toBilimClassPlan(plan): BilimClassLesson`,
которая переводит наш `content` в формат LMS. Скорее всего, потребуется
таблица соответствий секций: у нас 13 секций шаблона РК, у BilimClass свой набор.
Явно решить, что теряется при несовпадении.

**Шаг 3. Выгрузка интерактивов.** Наши задания — это ссылка на страницу
(`/plans/<id>` с интерактивом). Варианты: выгружать полный JSON задания либо
отдавать ссылку. Первый надёжнее, второй проще.

**Шаг 4. Кнопка и статус.** Кнопка «Отправить в BilimClass» на странице плана
у владельца. Показывать результат: `externalId`, ссылка на материал в LMS.
Хранить `external_id` в `lesson_plans`, чтобы повторная отправка обновляла
существующий материал, а не плодила дубли.

**Шаг 5. Ошибки и синхронизация.** Различать: неверный токен, превышение
квоты, материал не найден. Не ретраить 4xx. При рассинхронизации — кнопка
«Синхронизировать заново».

**Шаг 6. Тесты.** Мок HTTP-клиента: успешная отправка, 401 без тика,
идемпотентность повторной отправки, маппинг секций наsnapshot-тесте.

## Оценка

При наличии документации и токена — **M** (2–3 дня). Без документации
интеграция не начинается: угадывать контракт опасно, так как ошибка приведёт
к тихой порче данных у пользователей LMS.

## Что можно сделать сейчас без BilimClass

Экспорт в Word/HTML/ZIP уже покрывает потребность «передать план коллегам или
в методкабинет». Пока эта задача не закрыта, интеграция с LMS не является
блокером для продукта.
