# Панель администратора Mekty (`/admin`)

Серверная панель для просмотра пользователей, статистики использования и управления кодами активации.

## Настройка доступа

1. Найдите в базе MongoDB существующие `_id` пользователей (коллекция `users`). Получить ID можно из панели: она показывает ID всех пользователей, либо через `mongosh`:

   ```js
   db.users.find({}, { email: 1 }).limit(10)
   ```

2. Задайте переменную окружения **в среде развёртывания** (не в репозитории):

   ```
   ADMIN_USER_IDS=<24-hex Mongo ID>[,<ещё ID>...]
   ```

   - Разделитель — запятая; пробелы вокруг значений допускаются; регистр hex не важен.
   - **Используйте именно `_id` (ObjectId), а не email**: право определяется только совпадением с существующим пользователем, что исключает эскалацию через саморегистрацию с «админским» email.
   - Любое недопустимое значение (не 24-hex) в списке отключает панель целиком (fail closed).
   - Пустая/не заданная переменная = доступ запрещён всем.

   Пример для `.env.local` (только локально, не коммитится):

   ```
   ADMIN_USER_IDS=652f1a9b0c3d4e5f6a7b8c9d
   ```

3. Перезапустите/передеплойте приложение. Панель `/admin` доступна только после входа (`/login?next=/admin`); всем остальным возвращается 404 (страница не раскрывает своё существование).

## Что умеет панель

- **Статистика**: всего пользователей, действующие Pro/Free, записи учёта квоты КСП и изображений за текущий UTC-месяц, отдельная телеметрия провайдеров AI (запросы, ошибки, токены, среднее время) за месяц, счётчики кодов по статусам. Квота и телеметрия считаются по разным фильтрам и не смешиваются.
- **Пользователи**: пагинация (25 на страницу) и поиск по имени, email или точному Mongo ID. Поиск — литеральный текст, без regex-инъекций.
- **Коды активации**: создание по одному (`pro_1m`/`pro_1y`), **разовый показ кода открытым текстом только администратору**; в базе хранится только SHA-256 хеш (`billing_codes.codeHash`), в списках — только метаданные (статус, тип, даты, ID администраторов). Отзыв активного кода — с подтверждением; код со статусом `revoked` не может быть активирован (см. `redeemActivationCode`, фильтр `status: "active"`).

## Аудит и лимиты

- Создание и отзыв кодов пишут события `activation_code_created` / `activation_code_revoked` в коллекцию `plan_events` (`actor_id`, `code_id`, `code_type`, время). Обе операции транзакционные: сбой аудита откатывает изменение.
- Rate limits (Mongo-лимитер, ключ на администратора): чтение панели 60/мин; создание кодов 20/час; отзыв 60/час. Перед операцией проверяется доступность Mongo-лимитера; неуспех проверки даёт 503. Важно: общий `checkRateLimitAsync` при сбое самого обновления счётчика использует локальный fallback, поэтому эта проверка не гарантирует распределённый лимит при гонке со сбоем MongoDB.

## Безопасность

- Проверка прав выполняется на сервере в каждой точке входа (страница и оба server action), по подписанной сессии из `getCurrentUser` + `ADMIN_USER_IDS`. Данные клиента (email, роль, ID в запросе) никогда не используются для авторизации.
- Открытый текст кода существует только в успешном ответе `createAdminCodeAction`; ошибки MongoDB (например, дубликаты с хешем) наружу не пробрасываются, логи их не содержат.
- Панель помечена `noindex, nofollow`.

## Интеграция и проверка

- Нужен MongoDB replica set / Atlas с поддержкой транзакций. Standalone MongoDB не поддерживает атомарные создание/отзыв с аудитом; эти операции вернут 503.
- `mongo.ts` и `layout.tsx` не изменялись. Корректность использует существующий уникальный индекс `billing_codes.codeHash`. Для больших наборов данных стоит отдельно добавить индексы `{created_at:-1,_id:-1}` для users/billing_codes и `{status:1,created_at:-1,_id:-1}` для billing_codes; произвольный поиск подстроки может сканировать коллекцию, запросы ограничены 10 секундами.
- Условную ссылку `/admin` можно добавить в профиль на сервере через `isAdminUserId(user.id)` из `src/lib/admin/auth.ts`, где `user` получен из `getCurrentUser()`. Это только навигация; реальные проверки остаются в DAL/actions. Менять layout для охраны маршрута не требуется.
- Не подключайте аналитику записи сессий/содержимого форм к `/admin`. Код не сохраняется в localStorage, URL или аудит. Администратор может сохранить выданный код самостоятельно; после утраты ответа восстановить его невозможно — найдите созданную запись по ID/времени, отзовите и создайте новый код.
- Тесты без сети и базы: `npx vitest run tests/unit/admin-auth.test.ts tests/unit/admin-codes.test.ts tests/unit/admin-queries.test.ts`; статическая проверка: `npm run typecheck`.

## Ограничения (не входит в MVP)

- Панель не назначает права и не редактирует пользователей.
- Тариф вручную выдаётся через «Выдать Pro» ниже (продление от текущего срока, аудит `manual_pro_grant`).
- `ADMIN_USER_IDS` меняется только через среду развёртывания владельцем проекта.

## Модерация библиотеки

- Пользователи жалуются на чужие публичные планы кнопкой «Пожаловаться» (спам, оскорбления, ошибки, другое; 10 жалоб в час).
- Жалобы попадают в раздел «Жалобы на планы»: скрыть (план пропадает из библиотеки и по ссылкам для всех, кроме владельца), вернуть, закрыть жалобу. Скрытие/возврат пишут аудит `moderation_hide` / `moderation_unhide`.
- Пакет кодов — до 20 за раз, список показывается один раз (как одиночный код).
